# S1-S2 手动验证方法(工程基座 + 认证与用户设置)

> 接口范围:POST /api/auth/login|register|forgot-password|reset-password、GET /api/user/profile、GET|PUT /api/user/settings
> 数据库脚本:V01(建库)、V02(用户三表)、S01(demo 种子)

## 1. SQL 脚本执行(首测/零起点)

```powershell
# 建库(库尚不存在时,不附加 --database)

  mysql --host=127.0.0.1 --port=3306 --user=root --password=<你的密码> --default-character-set=utf8mb4

# 其余脚本(附加库名)
Get-Content .\backend\src\main\resources\db\V02__create_user_auth_tables.sql -Raw |

  mysql --host=127.0.0.1 --port=3306 --user=root --password=<你的密码> --default-character-set=utf8mb4 linguacraft
```

## 2. 接口验证(Swagger UI)

| # | 操作 | 预期 |
|---|---|---|
| 1 | POST /api/auth/login body `{"username":"demo","password":"123456"}` | code=0;data.token 非空;expiresIn=7200;user.id 为字符串 "1" |
| 2 | 同上但密码错误 | code=1001「用户名或密码错误」 |
| 3 | POST /api/auth/register(用户名 student01/密码 123456/昵称/邮箱) | code=0 直接返回 token(注册即登录) |
| 4 | 再次注册同名 | code=1002「用户名已存在」 |
| 5 | 注册短密码或非法用户名(如 `ab!`) | code=400 且 message 可读(如「密码长度至少 6 位」) |
| 6 | 不填 token 调 GET /api/user/profile | **HTTP 401** 且 body `{"code":401,...}` |
| 7 | Authorize 填 token 后 GET /api/user/profile | code=0;demo 档案(等级 5/青铜学习者/连续 21/累计 128) |
| 8 | GET /api/user/settings | 50 / 1 / us / false / ai / 08:00 |
| 9 | PUT /api/user/settings 仅传 `{"dailyWordGoal":20}` | code=0;重新 GET 仅该项变为 20,其余不变(部分更新) |
| 10 | PUT /api/user/settings 传 `{"accent":"xx"}` | code=400「口音仅接受 us 或 uk」 |
| 11 | POST /api/auth/forgot-password(demo 邮箱) | code=0;**后端控制台日志**出现重置链接(未配置 SMTP 时降级) |
| 12 | 复制日志中的 token 调 POST /api/auth/reset-password | code=0;新密码可登录;同一 token 二次使用 → code=400「重置链接无效或已过期」 |

## 3. SQL 抽查

```sql
SELECT id, username, password FROM user;              -- password 为 $2a$10$ 前缀 BCrypt 密文
SELECT * FROM user_setting WHERE user_id = 1;         -- 验证第 9 步修改已落库
SELECT token, used, expires_at FROM password_reset_token;  -- 重置完成后 used=1
```

## 4. 前端验证(关 MSW)

1. `frontend/.env.development.local` 写 `VITE_USE_MOCK=false`,`npm run dev`。
2. 登录页使用 demo/123456 真实登录 → 跳转 /dashboard。
3. 注册页/忘记密码/重置密码页可用;设置页保存后重新登录仍生效。
4. 退出(清除 token)后访问受保护页面 → 被路由守卫跳回登录页;token 失效时接口 401 也会被拦截跳登录。
5. 注意:首页 dashboard 的数据接口在 S3 及之后逐步补齐,早期访问会弹 404 提示,属预期。
