> 阶段:后台管理端计划的 A5。两块内容:概览页接入真实计数(替代 A1 只有一张自检卡的状态),
> 以及把 V08 加的 `role`/`enabled` 两列变成后台可操作的功能 —— 此前它们**只能改数据库**。

## 1. 交付内容

### 运营看板

`GET /api/admin/dashboard` → `AdminDashboardDto`,21 项计数。三条口径纪律(看板上每个数字都必须能在学生端复现):

| 纪律 | 做法 |
|---|---|
| "今日" | 一律 `created_at >= LocalDate.now().atStartOfDay()`,与首页 `HomeService.countTodayByType:114-121`、`UserService.stats` 同口径。**不用 `submitted_at`**(批改队列的排序才用它) |
| 待批改数不混算 | `practicePending` 只统计练习提交,与学生端 `stats.pendingGradingCount` 一致;模考的两类欠账分列 `examPending`(整卷 pending)与 `examWritingUngraded`(`partially_graded` 且 `writing_graded_at IS NULL`,即 A4-② 要人工判的那批) |
| 不动学生热路径 | 背单词三项镜像 `VocabService.todayTask()` 的字段语义(`first_learned_at` / `reviewed_at`),但**不调用该方法** —— 它按当前登录用户取数,看板要全站数字 |

数字一律用**基本类型**下发。项目把 `Long` 全局序列化成字符串(前端 id 契约),若用 `Long` 装计数,前端拿到的会是 `"15"` 而不是 `15` —— 与 `PageResult` 故意用 `long` 是同一个理由。

概览页 `views/admin/Overview.vue` 重排:待处理组置顶(练习待批改 / 模考作文待判 / 最久等待,并直达批改工作台)→ 题库 / 用户 / 今日活动 / 内容量四组 → A1 的权限自检卡保留 → 路线图。

### 用户管理

`/api/admin/users` 四接口:`GET` 列表(按注册时间倒序,支持关键词/角色/启用状态筛选)、`GET /{id}` 详情(资料 + 练习/模考/待批改/错题/已学长词计数 + 批改偏好)、`PATCH /{id}/status?enabled=`、`PATCH /{id}/role?role=`。

三条护栏(按优先级):

1. **不能停用自己、不能把自己降权** —— 否则管理员把自己关在门外且无法自救(后台入口本身要求 admin)。
2. **系统必须保留至少一个管理员** —— 停用"最后一个可用管理员"(`role=admin 且 enabled=1`)与降权"最后一个管理员"都拒绝。
3. 角色只接受 `student` / `admin`;两个 PATCH 在目标状态与当前一致时**直接返回成功且不写库**(前端重复点击不该报错)。

响应永不含密码字段(实体有 `password`,DTO 不列即不下发)。

### 已知的生效延迟(用户确认保持现状)

`JwtAuthFilter` 只解析令牌声明、不回查数据库,所以停用/降权**不影响已签发令牌**,最长到过期(2 小时)才真正生效;新登录立即被拒(`code 1001 账号已停用,请联系管理员`,与密码错误同码,不暴露账号状态)。本次不改过滤器(代价是每请求多一次查询),但在**看板与用户管理页都写明了这一点**,避免管理员以为"已停用"就等于"已踢下线"。

## 4. 踩坑记录

- **Naive UI 的 `n-select` 值不接受 boolean**:`options` 用 `value: true/false` 会 TS 报错(`Value = string | number`)。列表筛选这种三态(全部/是/否)统一用字符串 `'1'/'0'` 配 `clearable`,请求时再 `=== '1'` 转布尔。
- **`n-popconfirm` 没有 `disabled` 属性**:想按行禁用确认气泡里的按钮,得整条不套气泡、改渲染一个 `disabled` 的普通按钮,否则 `disabled` 只是"看起来能点"。
- **MyBatis-Plus 的 `updateById` 与 `insert` 一样有重载**:测试里 `verify(mapper, never()).updateById(any())` 因推断不明确编译失败,须写 `any(User.class)`。
- **计数别用 `Long` 装进 DTO**:全局 Jackson 规则会把 `Long` 序列化成字符串,前端 `{{ value }}` 能显示但参与比较/算术时会出问题。

## 5. 边界与已知取舍

- 看板是**即时聚合**,没有缓存与时间序列图;趋势类图表留给后续(学生端已有 `scoreTrend` 口径可复用)。
- 用户管理不做:删除账号、重置密码、批量操作、按学习量排序。停用是唯一"下架账号"的手段。
- 停用不改已签发令牌(见第 1 节),这是刻意的取舍而非缺陷;若要即时踢下线需引入令牌版本号或每请求回查。
- 角色只有 `student/admin` 两级,没有细粒度权限;`/api/admin/**` 整体要求管理员。
