# A1 后台权限与账号基座(手动验证方法)

> 阶段:后台管理端计划的 M1。目标是把"谁能进后台"这条链路打通并可验证,同时把后台的壳(布局/守卫/导航)立起来。
> 本阶段新增两个 SQL 脚本(V08、S07),均只增不改、幂等,已在本地库执行并复核。

## 1. 交付内容

### 数据库留痕

| 脚本 | 内容 | 幂等实现 |
|---|---|---|
| `V08__add_user_role_and_enabled.sql` | `user` 加 `role VARCHAR(10) NOT NULL DEFAULT 'student'`、`enabled TINYINT(1) NOT NULL DEFAULT 1`、`KEY idx_user_role` | MySQL 8 无 `ADD COLUMN IF NOT EXISTS`,改用 `information_schema` 判重 + `PREPARE/EXECUTE` 动态执行(不依赖客户端 `DELIMITER`) |
| `S07__seed_admin_account.sql` | 管理员账号 `admin / 123456`(`role=admin`、`enabled=1`)+ 其 `user_setting` 默认行 | `user` 以用户名唯一键 `ON DUPLICATE KEY UPDATE`;**不指定主键 id**,避免与用户已注册账号冲突而误改他人角色 |

BCrypt 密文与 `S01` 完全一致(即口令 123456),避免重复生成密文;脚本内已注明"本地演示口令,对外环境必须改密"。

### 权限链路(五层)

1. **库表**:`user.role`(student/admin)+ `user.enabled`。
2. **登录签发**:`JwtUtil.generateToken(userId, username, role)` 写入 `role` 声明;`AuthService.login` 增加 `enabled` 校验,`register` 强制 `role=student`。
3. **请求解析**:`JwtAuthFilter` → `JwtUtil.parsePrincipal(token)`(返回 `record JwtPrincipal(Long userId, String role)`),把角色转成 `ROLE_ADMIN` / `ROLE_STUDENT` 权限;旧令牌无 role 声明时按 student 兜底(不提权)。
4. **授权与错误体**:`SecurityConfig` 在 `anyRequest()` 之前插入 `/api/admin/** → hasRole("ADMIN")`,并注册 `RestAccessDeniedHandler`(新增 `ResultCode.FORBIDDEN(403,"无权限访问")`),使 401/403 都返回统一响应体。
5. **前端**:`UserProfile.role` → `useUserStore.isAdmin` → 路由守卫(`meta.adminOnly` 时 `ensureProfile()` 后校验,非管理员弹回 `/dashboard`)+ 顶部导航"管理"入口与头像菜单"进入后台"按 `isAdmin` 显隐。

新增页面/文件:`layouts/AdminLayout.vue`(独立布局:顶栏含"返回学生端"与主题切换,左侧菜单取 `adminNav`)、`views/admin/Overview.vue`(权限自检卡 + A2~A5 路线图)、`api/admin.ts`(`getAdminPing`)、`types/admin.d.ts`;后端新增 `AdminSystemController`(`GET /api/admin/ping`)与 `AdminPingResponse`。

管理端接口**不注册 MSW handler**:`main.ts` 为 `onUnhandledRequest: 'bypass'`,未匹配路径直连真实后端。

## 3. 你如何复现验证

```powershell
# 1) 结构 + 种子(可重复执行)
cd c:\Users\ASUS\Documents\LinguaCraft\backend
Start-Process -FilePath "$env:USERPROFILE\mysql-8.4.7-winx64\bin\mysql.exe" `
  -ArgumentList '--host=127.0.0.1','--user=root','--password=<你的密码>','--default-character-set=utf8mb4','linguacraft' `
  -RedirectStandardInput src\main\resources\db\V08__add_user_role_and_enabled.sql -NoNewWindow -Wait
# 同理执行 S07__seed_admin_account.sql

# 2) 启动后端
.\mvnw.cmd clean compile; .\mvnw.cmd spring-boot:run

# 3) 三种令牌分别打管理接口(用 curl 才能同时看到 HTTP 状态与响应体)
$b='http://127.0.0.1:8080'
$admin=(Invoke-RestMethod -Method Post -Uri "$b/api/auth/login" -ContentType 'application/json' -Body '{"username":"admin","password":"123456"}').data.token
$demo =(Invoke-RestMethod -Method Post -Uri "$b/api/auth/login" -ContentType 'application/json' -Body '{"username":"demo","password":"123456"}').data.token
curl.exe -s -w "`nHTTP=%{http_code}`n" -H "Authorization: Bearer $admin" "$b/api/admin/ping"   # 期望 code=0 且 role=admin
curl.exe -s -w "`nHTTP=%{http_code}`n" -H "Authorization: Bearer $demo"  "$b/api/admin/ping"   # 期望 code=403 / HTTP 403
curl.exe -s -w "`nHTTP=%{http_code}`n" "$b/api/admin/ping"                                     # 期望 code=401 / HTTP 401

# 4) 前端:关 MSW(VITE_USE_MOCK=false)→ npm run dev
#    用 admin 登录 → 顶部出现「管理」入口、头像菜单出现「进入后台」→ /admin/overview 四张卡显示探针结果;
#    用 demo 登录 → 无「管理」入口,手输 /admin/overview 会被弹回 /dashboard。
```

## 4. 踩坑记录

- **Spring Security 7 包路径变更**:`AccessDeniedHandler` 从 `org.springframework.security.web` 移到 **`org.springframework.security.web.access`**,而 `AuthenticationEntryPoint` 仍在原包 —— 两者不再同包,照旧习惯写 import 会编译失败。
- **判定"登录被拒"不能只看是否抛异常**:本项目业务错误(1001 等)仍是 HTTP 200,`Invoke-RestMethod` 不会抛异常。必须读响应体的 `code`,否则会误判成"登录成功"。
- 中文响应体在 PowerShell 5.1 下显示为乱码属客户端解码问题(见 A0 文档);核验字节用 `curl.exe -o 文件` 或 SQL 端 `HEX()`。

## 5. 边界与已知取舍

- 角色与停用状态读自**令牌声明 / 登录时校验**,因此改角色或停用后,该用户已签发的旧令牌在有效期内(2 小时)仍可访问其已授权范围;要即时失效需引入令牌版本号或每请求回查(留给后续)。
- 前端守卫只负责可用性(隐藏入口、弹回首页),安全边界以后端 403 为准;不能因为前端隐藏了入口就认为接口安全。
- 后台按桌面优先设计(左侧常驻菜单),手机窄屏下仍可用但未做专属排版;A2~A5 的表格页会一并优化窄屏表现。
