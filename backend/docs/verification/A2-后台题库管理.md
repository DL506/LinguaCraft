# A2 后台题库管理(手动验证方法)

> 阶段:后台管理端计划的 M2。目标是让管理员能在后台**录入、编辑、上下架、删除**题目,
> 并且在写入口就把"答案永不下发"这条不变量守住 —— 即 `content`(下发列)与 `answer_key`(答案列)由服务端强制分离与校验。
> 本阶段**无数据库结构变更、无新增种子脚本**(`question` 表自 V03 起已具备全部所需列)。

## 1. 交付内容

### 后端接口(6 个,命名空间 `/api/admin/questions`)

| 方法 | 路径 | 作用 | 关键约定 |
|---|---|---|---|
| GET | `/api/admin/questions` | 分页列表 | 筛选 `type/sourceType/status/keyword`;每项附带 `refSubmissionCount`(被提交引用数);**含下架题** |
| GET | `/api/admin/questions/{id}` | 详情 | 唯一返回 `answerKey` 的题目详情接口 |
| POST | `/api/admin/questions` | 新建 | `id` 留空则服务端生成 `{type}-{source}-{yyMMddHHmmss}` |
| PUT | `/api/admin/questions/{id}` | 更新 | 整条覆盖 `content`/`answer_key`;**题型不可变更** |
| PATCH | `/api/admin/questions/{id}/status?status=0\|1` | 下架/上架 | 只改 `status` 一列 |
| DELETE | `/api/admin/questions/{id}` | 物理删除 | 引用保护:被提交或错题引用即拒绝 |

权限沿用 A1:`SecurityConfig` 的 `/api/admin/** → hasRole("ADMIN")`,学生令牌 403、未登录 401。

新增文件:`controller/AdminQuestionController.java`、`service/AdminQuestionService.java`、
`dto/admin/QuestionUpsertRequest.java`、`QuestionAdminListItemDto.java`、`QuestionAdminDetailDto.java`。

### 五道写入校验(落库前,任一不过即 `code=400` 并给出定位路径)

| # | 校验 | 拒绝示例 |
|---|---|---|
| 1 | 结构:按题型核对关键字段 | `content.questions[2].options 至少需要 2 个选项` |
| 2 | 答案防呆:递归禁止 `content` 出现 `answer/explanation/sampleAnswer/acceptAlternatives` | `content 禁止包含答案类字段 content.questions[0].answer` |
| 3 | 编号集合一致:`answer_key` 的 id 集合必须与 `content` **完全相等**(不多不少、不重复) | `answer_key 的编号集合必须与 content 完全一致(题目:[1,2,3],答案:[1,3])` |
| 4 | 答案合法:客观题 `answer` 必须落在该项候选 key 集合内(五选五另要求答案互不重复) | `answer_key.blanks[1].answer=E 不在该空选项 [A,B,C,D] 中` |
| 5 | 占位符一致:`passage` 里 `[[n]]` 的编号集合必须等于 `blanks` 的 id 集合 | `passage 中的 [[n]] 占位符集合 [1,2] 与 blanks 编号集合 [1,2,3] 不一致` |

校验 2 是本阶段最重要的防线:只要写入成功,`content` 列里就**不可能**有答案,学生端只读 `content` 的既有约定无需再改。

另有三条写入约束:`content.id/type/source` 由服务端**强制覆写**为权威值(不接受请求里的值);
分值一律取 `PracticeRules` 按题型默认映射(请求无法覆盖,避免与判分口径分叉);
`hasAnswer` 由题型推导(写作走 AI/人工评分为 `false`,其余为 `true`)。

### 前端(3 个新页面/改动 + 2 处基础设施)

- `views/admin/Questions.vue`:筛选条 + `n-data-table`(`scroll-x: 1180`,窄屏横向滚动)+ 分页;
  行内操作为编辑 / 上下架 / 删除,**`refSubmissionCount > 0` 时删除按钮直接置灰**,确认气泡里说明原因。
- `views/admin/QuestionEdit.vue`:新建与编辑共用(路由含 `id` 即编辑模式并反填表单)。
  分题型结构化表单(阅读=题干+四选项;完形=空位+四选项;五选五=候选句每行一条;语法填空=提示词+可接受变体;作文=prompt+要点+字数+评分维度+范文)。
- **JSON 面板为最终提交口径**:表单任何改动实时重新生成 `content`/`answer_key` 两个 JSON;
  一旦手工编辑过 JSON,界面顶部出现黄色提示并且表单变化不再覆盖它,保存时以面板内容为准(保存前本地预检答案防呆与占位符一致,少一次无谓往返)。
- `api/request.ts` 新增 `patch()`;`router/routes.ts` 新增 `questions`、`questions/new`、`questions/edit/:id`(后两者顺序在参数路由之前声明);`router/nav.ts` 的 `adminNav` 增"题库管理"。
- 管理端接口依旧**不注册 MSW handler**(`onUnhandledRequest: 'bypass'`),因此后台功能只在 `VITE_USE_MOCK=false` 接真实后端时可用。

### 顺带修掉的两处缺口(非新增功能,属 A2 必要修正)

1. **CORS 未放开 PATCH**:`WebConfig` 与 `SecurityConfig` 两处 `allowedMethods` 原本只有 `GET/POST/PUT/DELETE/OPTIONS`。
   经 vite 代理(同源)时不会触发预检所以看似正常,但一旦前端不经代理直连后端(其他端口实例、Apifox 网页版),上下架的 PATCH 预检会被浏览器拦掉,两处均已补 `PATCH`。
2. **更新会清空来源 meta**:录入表单不暴露 `sourceMeta`,而 PUT 原先无条件用请求值重建 `{type, meta}`,
   导致编辑任何一道 `S02` 真题后其 `year/region`(或教师名)就丢失。现改为**请求未提供 meta 时沿用库中原值**,
   并且 `content.source` 与 `source_meta` 列由同一个节点写入(否则学生端显示的来源会与后台记录不一致)。
   同处把详情接口的 `sourceMeta` 归一化为 `meta` 子对象,与前端 `AdminQuestionDetail.sourceMeta` 的类型注释对齐。

## 4. 踩坑记录

- **Jackson 3 的两处 API 变化**(与 S9 同源):`JsonNode.deepCopy()` 统一返回 `JsonNode`,不再像 Jackson 2 那样在 `ObjectNode` 上协变覆写,故 `ObjectNode content = (ObjectNode) raw.deepCopy();` 必须显式强转;遍历对象成员用 **`node.properties()`**,`fields()` 已不存在。
- **`code=400` 不等于 HTTP 400**:本项目的业务错误统一走 HTTP 200 + 响应体 `code`,所以前端 `request` 层的错误提示不能依赖 HTTP 状态码。
- **CORS 的两份配置要同时改**:`WebConfig`(MVC 级)与 `SecurityConfig.corsConfigurationSource()`(Security 的 `.cors()` 用的才是真正生效的那份,因为 `csrf disable + cors(defaults)` 走 Security 链)。只改一处会在不同访问方式下表现不一致。
- **参数路由与字面量路由的声明顺序**:`questions/new` 必须与 `questions/edit/:id` 分开写并把编辑路径带上 `edit/` 前缀,否则新建页会被参数路由匹配掉。

## 5. 边界与已知取舍

- JSON 面板是权威提交内容,结构化表单只是"生成器":手工改过 JSON 后表单不再反向覆盖它(界面已提示),这是有意为之,便于录入复杂结构而无需为每种边角情况加表单控件。
- 分值不提供手工入口:练习判分口径由 `PracticeRules` 统一,允许覆盖会让题目分值与判分/统计分叉;确有特殊分值需求应改判分规则而非改题目。
- 题型不可变更:历史提交与错题记录保存的是作答时的题型快照,允许改题型会让旧数据无法复现;需要换题型请新建一道并下架旧的。
- 删除是物理删除且带引用保护(提交 + 错题两处),因此"想停止投放"请一律用下架;下架不影响已发生的提交详情与错题重做。
- 来源 meta(年份/地区/教师名)暂无表单输入口,更新时按原值保留;需要录入真实 meta 目前只能走数据库或后续补充字段。
- 批量导入(Excel/JSON)与 AI 出题入库审核流不在本阶段;A4 批改工作台会复用本阶段的列表与详情契约。
