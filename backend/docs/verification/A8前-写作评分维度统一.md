# A8 前置 · 写作评分维度统一为 4 项(内容要点 / 语言表达 / 篇章结构 / 格式规范)

> 2026-10-12。这不是一批功能,而是一条**评分口径拍板 + 数据落地**:用户裁定应用文的"格式"独立成一个给分维度,
> 于是全项目写作题面统一为 4 维。排 A8 之前做,是因为它同时影响**已交付的 A7 预评**与将要做的 A10 校核。

## 1. 为什么原来不一致

| 来源 | 维度数 | 证据 |
|---|---|---|
| 种子真题题面 | 3 | `db/S02__seed_questions.sql` 的 `writing-real-2023-1` / `writing-teacher-1` |
| 真题卷写作部分 | 3 | `db/S03__seed_exam_2026.sql` 的 `sections[4].content.scoringDimensions` |
| **AI 出题提示词** | **4** | `ai/PromptTemplates.java:73` 要求 `["内容要点","语言表达","篇章结构","格式规范"]` 且"恰好 4 项" |
| 后台新建题默认值 | 4 | `frontend/src/views/admin/QuestionEdit.vue:200` 的 `dimensionsText` 默认串 |

后果是实测出来的:AI 生成的 `writing-ai-mv2y20cd` 题面 4 维、真题题面 3 维,而 A7 预评的建议分是**按题面维度实算**
(`WritingGradeSupport.toPreview`),于是同一份判分抽屉批真题显示 3 行、批 AI 题显示 4 行,两套分项口径不可比。

任务书 r1/r2/r3 只写"作文展示评分维度和范文",**没有规定维度名**,所以口径不是从规格来的,是用户这次定的。

## 2. 这次改了什么

- `db/V10__normalize_writing_dimensions.sql`(新增,幂等):题库全部写作题题面 + 每张卷面写作部分题面补 `格式规范`。
  用 `JSON_ARRAY_APPEND` 而不是整体覆写,保留原有顺序与可能存在的自定义维度名;卷面路径由 `JSON_SEARCH` 在运行时定位
  (`$.sections[i].type` → `$.sections[i].content.scoringDimensions`,`ExamPaperValidator` 保证一张卷恰好一个写作部分)。
- `db/S02__seed_questions.sql` / `db/S03__seed_exam_2026.sql`:种子直接改成 4 维,保证**全新库与老库口径一致**(否则新装环境又会分叉)。
- `frontend/src/mocks/data/writing.ts`(2 处)/ `mocks/data/exam.ts`(1 处):演示数据同步 4 维。
- `db/README.md`:V10 入索引,并写明"种子与 V10 必须一致"。
- **零 Java 改动**:闸门只要求 `scoringDimensions` 是非空数组(`QuestionContentValidator.java:91`),判分只看各维度之和对 `cap` 封顶,
  维度个数不参与分值计算 —— 所以 3→4 不动任何已有分数,也不动判分代码。

## 4. 有意没动的东西

- **历史判分快照** `writing_result`:已 graded 的件保留当时维度记录。全库只有提交 `#4`(AI 生成写作题)有 `writing_result`,它本来就是 4 维,所以不存在需要回填的 3 维历史数据。
- 测试夹具里的 1/2 维数组(`ExamPaperValidatorTest`、`AiGradingServiceTest` 等):它们是**结构夹具**,不是口径,不动。
- 判分与预评代码:`dimensionCap = 100`(单维输入上限)与"合计 ≤ 卷面总分"的校验都与维度个数无关。

## 5. 回滚方法

维度是题面数据,回滚只涉及库:

```sql
-- 移除"格式规范"(仅写作题面与卷面写作部分)
UPDATE question SET content = JSON_REMOVE(content, '$.scoringDimensions[3]')
WHERE type='writing' AND JSON_UNQUOTE(JSON_EXTRACT(content,'$.scoringDimensions[3]'))='格式规范';
-- 卷面同理对 JSON_SEARCH 定位到的路径 JSON_REMOVE;或直接用备份:
mysql -h 127.0.0.1 -uroot linguacraft < backend/target/backup-pre-V10-20261012-051234.sql
```

同时把 `S02`/`S03` 与两处 mock 的维度串改回 3 项,否则下次重灌种子又变 4 维。
