# 打包与部署(可执行 war:内置前端 dist,两用)

> 2026-10-14。**同一份 `linguacraft.war` 两用**:`java -jar` 起内嵌 Tomcat 直接出页面;也可以原样丢进外部 Tomcat 11。
> 前端 dist 打进产物里,所以"机器上只有一个 JRE"的场景不需要 nginx 也能跑起来。

## 1. 怎么打

```bash
cd frontend && npm run build                    # 产出 frontend/dist
cd ../backend && ./mvnw.cmd clean package       # → backend/target/linguacraft.war(约 126 MiB,含 177 个前端文件)
```

`frontend/dist` 不存在时构建**只跳过不报错**,产物就是个纯接口包 —— 启动日志会明说(见 §4)。

## 2. 场景一:环境只有一个 JRE(必须 ≥21)

```bash
java -jar target/linguacraft.war --server.port=8081
```

打开 `http://localhost:8081/` 就是登录页(页面与接口同源,不需要任何反代)。

- 本机 8080/5173 被另一个项目 theca 占着,所以这里写 8081;
- 仍然**需要 MySQL 在跑**(数据目录 `C:\Users\ASUS\mysql-8.4.7-winx64\Data`);
- `LC_AI_*` / `LC_JWT_SECRET` / `LC_DB_PASSWORD` 没显式注入时,启动日志逐项 WARN(用的是 `application.yml` 里的内置默认值)。

## 3. 场景二:nginx + 外部 Tomcat 11.0.27

**war 必须部署成 `ROOT`**。前端接口前缀是硬编码的 `/api`(`frontend/src/api/request.ts:10`,没有环境变量分支),
所以只要应用带了 context path(如 `/linguacraft`),全站接口就会 404。

```bash
cp backend/target/linguacraft.war "$CATALINA_BASE/webapps/ROOT.war"
```

Tomcat 侧的硬约束:**必须 11.0.x**(Spring Boot 4.1 走 Servlet 6.1,10.1 / 9 部署不起来),
运行 Tomcat 的 JVM 也要 JDK 21+。

环境变量:用 `bin/startup.bat` 启动时,Tomcat 继承**调用它的那个 shell** 的环境,所以在同一个 Git Bash 里:

```bash
cd backend && set -a && . ./.env.local && set +a && cd "$CATALINA_HOME" && bin/startup.bat
```

若把 Tomcat 注册成 Windows 服务,环境变量得单独配到服务上,上面这行就不起作用了。

nginx 侧要点(每条都对着本仓库的实测值):

```nginx
server {
  listen 80;
  server_name linguacraft.example;
  root /var/www/linguacraft/dist;          # 前端 nginx 出,war 里那份不会被请求

  location / { try_files $uri $uri/ /index.html; }        # 路由是 createWebHistory,少了这行刷新就 404

  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 8m;               # 必须 ≥ 后端 multipart 上限(application.yml 是 5MB/6MB),否则单词 CSV 导入被 413
  }

  location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
  location ~* /(index\.html|sw\.js|manifest\.webmanifest)$ { add_header Cache-Control "no-cache"; }  # PWA 是 autoUpdate
  # 只放 /api,不写 location / { proxy_pass } —— 后者会把 /actuator 一起暴露
}
```

## 4. 这次打包改造动了哪四处

| 位置 | 改动 | 为什么 |
|---|---|---|
| `pom.xml` | `packaging=war`;`spring-boot-starter-tomcat` 设 `provided` | 前者才能出可执行 war;后者让容器落到 `WEB-INF/lib-provided`(实测 4 个 jar),外部 Tomcat 会忽略它,不与容器自带的重复 |
| `ServletInitializer`(新增) | 继承 `SpringBootServletInitializer` | 外部容器不调 `main`,必须回调这里 |
| `SecurityConfig` | 授权面由"非白名单一律要登录"改成**只有 `/api/**` 要登录** | 原来 `.anyRequest().authenticated()` 把 `/`、`/assets/*`、前端路由全吃了 → war 里带着 dist,`java -jar` 打开仍是 401 白屏。全部 16 个控制器都在 `/api` 下(实测),所以**放行页面不等于放行数据** |
| `WebConfig` | 加 SPA 顶层路由的 `forward:/index.html` | 直接访问 `/admin/exam-papers` 服务器侧没有这个文件。**刻意不用通配**:通配会把 `/api/xxx` 的 404 吞成"200 + 一段 HTML",前端 `res.json()` 炸在解析上。新增前端顶层路由时要同步加一行 |

dist 的拷贝目标是 **`target/classes/static`**,不是 `src/main/resources/static` —— 后者会往源码树里写几 MB 产物,`git status` 变脏且 `mvn clean` 删不掉。

## 5. 验证到哪一步了(诚实版)

- `./mvnw.cmd clean package` → **173 例全绿**(新增 `SpaDeploymentSecurityTest` 5 例:SPA 路径与静态路径不再 401、`/api/**` 三处仍 401、`/api/does-not-exist` 不被回退成页面、`/api/system/ping` 与 `/actuator/health` 不变);
- 产物结构逐项核过:`Main-Class: ...WarLauncher`、`Start-Class: BackendApplication`、`static/` 177 个文件(含 `index.html`/`sw.js`)、`WEB-INF/lib` 168、`lib-provided` 4、`ServletInitializer.class` 在 `WEB-INF/classes`;
- 归档:`jar-archive/linguacraft-war-20261014-230526.war`(该目录已 gitignore);
- **已实机验证(2026-10-14,用户跑通后交付同事)**:`java -jar` 起页面正常,`/admin/exam-papers` 这类前端路由刷新能落到 `index.html`
  (即容器内的 FORWARD 派发确实生效,不只是 MockMvc 层面的映射)。

## 6. 交给别人之前必须处理

war 会把 `application.yml` 一起打进 `WEB-INF/classes/`,里面内联了两项明文默认值:**DB 口令**与
**JWT 签名密钥** `LC_JWT_SECRET:linguacraft-dev-secret-change-me-…`(`application.yml:76`)。
后者尤其要紧:**接收方若没显式注入 `LC_JWT_SECRET`,任何拿到这个 war 或本仓库的人都能签出合法的 admin 令牌**,
直接调 `/api/admin/**`;启动自检目前只是 WARN,不拦。
两个处置:让部署方立刻设上该环境变量(不用重新打包),或把它改成"缺失即拒绝启动"(更硬,会动本地 dev 流程)。
注意这两项默认值已经在 git 历史里并推到 GitHub,确认过仓库可见性才算闭环。
